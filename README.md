# kotha-audio

Static host for the assets behind a **captioned phone call prototype** built on Twilio.

Twilio's trial tier won't accept inline TwiML, so TwiML documents are hosted here
as static files alongside the audio clips they reference. Everything committed to
the root of `main` is served over HTTPS by GitHub Pages within about a minute.

## Important: play.xml cannot be a Twilio webhook

GitHub Pages is a static host - it answers only GET and HEAD, and returns
405 Method Not Allowed for POST. Twilio fetches webhook URLs with POST by
default, and on a **trial account** the `method` parameter is rejected
(HTTP 400, "trial accounts have limited parameter access"), so GET cannot
be forced.

Net effect: **host the TwiML somewhere that accepts POST** (a TwiML Bin is
free and Twilio-hosted), and keep pointing its `<Play>` at the audio URLs
below. Audio is always fetched with GET, so this repo remains the right
home for the mp3s.

`play.xml` is kept here as the canonical copy of the markup - paste it into
the TwiML Bin.

## Using it from Twilio

Point your Twilio number's **Voice webhook** at the TwiML document:

```
https://jawaad512.github.io/kotha-audio/play.xml
```

The TwiML in turn references an audio clip by its full public URL:

```xml
<Response>
  <Pause length="1"/>
  <Play>https://jawaad512.github.io/kotha-audio/TTStest.mpga</Play>
  <Pause length="3"/>
</Response>
```

## Adding files

```bash
./publish.sh greeting.mp3 flow-b.xml
```

Copies the files in, commits, pushes to `main`, refreshes the URL table above,
and prints the public URL for each. Run it bare to publish anything you've
already dropped into the folder. Pass `--force` to overwrite a live file without
being prompted.

## Layout

Everything sits flat at the repo root. That's deliberate: `TTStest.mpga` is
already live with a Twilio call pointing at it, and GitHub Pages serves paths
literally with no redirects — so moving a published file breaks its URL
permanently. A flat root means no file ever *needs* to move, and the generated
table above does the job folders would otherwise do.

| File | Purpose |
| --- | --- |
| `*.xml` | TwiML documents — one per call flow |
| `*.mp3` | Audio clips as added — greetings, test phrases, TTS output |
| `*.mpga` | Byte-identical twins of the mp3s, served as `audio/mpeg` for Twilio |
| `publish.sh` | One-command publish + README regeneration |
| `.nojekyll` | Serve files as-is instead of running them through Jekyll |
| `.gitattributes` | Marks audio binary so line-ending conversion can't corrupt it |

## Why .mpga and not .mp3

GitHub Pages sets `Content-Type` from the file extension and offers no way to
override it — no custom headers, and `_headers` is a Netlify/Cloudflare feature
that Pages ignores. It serves `.mp3` as `audio/mp3`, a non-standard alias that
is **not** among the content types Twilio documents for `<Play>`, and which can
surface as Twilio error 12300.

Measured against this repo:

| Extension | Served as |
| --- | --- |
| `.mp3` | `audio/mp3` |
| `.mpga` | `audio/mpeg` ← use this in TwiML |
| `.mp2`, `.m2a` | `audio/mpeg` |
| `.mpeg` | `video/mpeg` |
| `.mpa` | `application/octet-stream` |
| `.xml` | `application/xml` |

So each clip is published twice and `publish.sh` maintains the twins for you.

## Notes

- Everything here is public. Don't commit anything sensitive — no caller audio,
  no recordings of real conversations.
- Pages sends `Cache-Control: max-age=600`. Replacing a file in place can take
  up to ten minutes to propagate; publishing under a new name is instant.
- Renaming or deleting a published file breaks its URL with no redirect. If a
  Twilio call points at it, the call fails. `publish.sh` prompts before
  overwriting for this reason.
